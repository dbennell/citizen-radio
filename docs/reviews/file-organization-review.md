# File Organization Review

## Overview
This document reviews the current file organization in the CitizenRadio project, focusing on identifying all types of files generated by the application and providing recommendations for better organization, particularly for metadata files.

## Current File Organization

### Directory Structure
The project currently organizes files across several directories:

1. **Data Directory** (`/data`):
   - `archive/` - Archived content organized by type (dj, podcast)
   - `cache/` - Cache files
     - `segue-text/` - Cached segue text
     - `tts/` - Cached text-to-speech content
   - `holding/` - Content on hold (not in rotation)
     - `images/` - Image files
     - `prompts/ads/` - Ad prompt text files
   - `ready/` - Content ready for playback
     - `ad/` - Advertisements
     - `dj/` - DJ content
     - `image/` - Images
     - `intro/` - Introductions
     - `music/` - Music tracks
     - `podcast/` - Podcast content
     - `segue/` - Segue content
   - Log files:
     - `chat.log` - Chat log
     - `feedback.log` - Feedback log
     - `play.log` - Play log
     - `ratings.log` - Ratings log
   - Metadata files:
     - `audio-analysis.json` - Central audio analysis database

2. **Temp Directory** (`/temp`):
   - `ad/` - Temporary ad files
   - `clips/` - Temporary clip files
   - `dj/` - Temporary DJ content
   - `intro/` - Temporary intro content
   - `podcast/` - Temporary podcast content
   - `segway/` - Temporary segway content (note spelling difference from "segue")

### File Types Generated

Based on code analysis, the application generates the following types of files:

1. **Log Files**:
   - Play logs (`play.log`) - Records of played content
   - Chat logs (`chat.log`) - Records of chat messages
   - Feedback logs (`feedback.log`) - User feedback
   - Ratings logs (`ratings.log`) - Content ratings

2. **Audio Analysis Files**:
   - Central audio analysis database (`audio-analysis.json`)
   - Individual track analysis files (`[Track Name].analysis.json`)

3. **Cache Files**:
   - Segue text cache (`cache/segue-text/`)
   - Text-to-speech cache (`cache/tts/`)

4. **Metadata Files**:
   - Analytics data (`analytics.json`) - Referenced in code but not found in filesystem
   - Recommendations data (`recommendations.json`) - Referenced in code but not found in filesystem
   - Wave data (`waves.json`) - Referenced in code but not found in filesystem
   - Request data (`requests.json`) - Referenced in code but not found in filesystem
   - Voice mapping data (`voiceMapping.json`) - Referenced in code but stored in src/managers/

5. **Temporary Files**:
   - Streaming playback temp files
   - Content generation temp files
   - Overlay image temp files

6. **Content Files**:
   - Audio files (MP3)
   - Image files (PNG)
   - Text files (TXT)

## Issues Identified

1. **Metadata File Dispersion**:
   - Metadata files are scattered across different locations
   - Some metadata is stored alongside content (e.g., track analysis files)
   - Some metadata is stored in the root data directory
   - Some metadata is referenced in code but not found in the filesystem

2. **Inconsistent Naming**:
   - "segue" vs "segway" naming inconsistency between directories

3. **Temporary File Management**:
   - Temporary files are stored in a separate directory at the project root
   - No clear cleanup mechanism for temporary files

4. **MP3 File Metadata**:
   - The current system stores analysis data in separate files rather than embedding it in MP3 tags

## Recommendations

### 1. Centralized Metadata Directory

Create a dedicated `/data/metadata/` directory to store all metadata files:

```
/data/
  /metadata/
    analytics.json
    audio-analysis.json
    recommendations.json
    requests.json
    voice-mapping.json
    waves.json
```

This would:
- Keep metadata files organized in one location
- Make it easier to back up or manage metadata
- Improve discoverability of metadata files

### 2. MP3 Tag Utilization

As mentioned in the requirements, MP3 files can store metadata in their internal tags. Consider:

- Embedding key analysis data (BPM, energy, mood) directly in MP3 tags
- Keeping detailed analysis in separate files for advanced features
- Creating a utility to synchronize between MP3 tags and analysis files

This would:
- Make MP3 files more portable with their essential metadata
- Support the workflow of moving files between directories
- Allow other software to access basic metadata

### 3. Consistent Temporary File Management

Improve temporary file management by:

- Moving the `/temp` directory under `/data/temp` for consistency
- Implementing a cleanup mechanism for temporary files
- Using consistent naming (standardize on "segue" vs "segway")

### 4. Log File Organization

Create a dedicated `/data/logs/` directory to store all log files:

```
/data/
  /logs/
    chat.log
    feedback.log
    play.log
    ratings.log
```

This would:
- Keep log files organized in one location
- Make it easier to apply log rotation or archiving

### 5. Cache Management

The current cache organization is good, but could be improved by:

- Adding a cache expiration mechanism
- Implementing cache size limits
- Adding a cache cleanup utility

## Implementation Priority

1. **High Priority**:
   - Create the metadata directory and move existing metadata files
   - Standardize naming conventions (segue vs segway)

2. **Medium Priority**:
   - Implement MP3 tag utilization
   - Create the logs directory and move log files

3. **Low Priority**:
   - Reorganize temporary files
   - Implement cache management improvements

## Conclusion

The current file organization has a good foundation with content organized by type and state (ready, holding, archive). The main area for improvement is the organization of metadata files, which could be centralized in a dedicated directory.

By implementing these recommendations, the project will have a cleaner file structure, better metadata management, and improved support for workflows involving moving MP3 files between directories.
